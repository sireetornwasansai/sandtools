# สารบรรณอิเล็กทรอนิกส์ (SAND Office Tools v1.7.0)

ทะเบียนเดียวสำหรับ **หนังสือรับ + หนังสือส่ง** ของหน่วยงาน — ย้ายแนวคิดจากระบบสารบรรณเดิม (ลงรับ · ทะเบียนรับ · ติดตามหนังสือ) มาไว้ในแอปนี้
หน้า “หนังสือรับเข้า” (Telegram) กลายเป็น **คิวรอลงรับ** และใช้ **ตัวนับเลขรับชุดเดียวกัน** กับหน้าสารบรรณ — เลขไม่ชนกัน

## ติดตั้ง (ครั้งเดียว)
1. วางไฟล์ `gas/Saraban.gs` (ใหม่) และแทนที่ `Code.gs`, `Inbox.gs`, `appsscript.json` ใน Apps Script (ไฟล์ `Analytics.gs`, `Library.gs`, `Links.gs` ใช้ของเดิมที่คุณมีอยู่ — ฉบับ Analytics ใน GitHub เก่ากว่าของคุณ อย่าทับ)
2. รัน `setupSaraban()` หนึ่งครั้ง → สร้างแท็บ `Saraban`, `SarTo`, `SarTrack`, `SarUnits`, `SarNo` และหน่วยงานตั้งต้นของโรงพยาบาล (แก้ได้ในหน้า “หน่วยงาน”)
3. ตั้ง Script properties: `SAR_ORG_NAME` (ชื่อหน่วยงานบนตรารับ) · `SAR_BOOK_PREFIX` (เช่น `สธ 0123.4` ใช้ทำเลขที่หนังสือส่ง) · `SARABAN_STAFF_EMAILS` · `SARABAN_EXEC_EMAILS` · `SARABAN_SECRET_EMAILS` (ผู้ได้รับอนุญาตดูหนังสือลับ — ต้องอยู่ใน STAFF ด้วยจึงลงรับได้) · `SAR_HOLIDAYS` (วันหยุดราชการ `2026-12-10,…`) · `SAR_SLA_DAYS` (ค่าเริ่มต้น `7,3,1,0` = ปกติ,ด่วน,ด่วนมาก,ด่วนที่สุด วันทำการ — **ปรับให้ตรงระเบียบของหน่วยงาน**)
4. Deploy เป็นเวอร์ชันใหม่ (ขอสิทธิ์ใหม่ได้ — ใช้ Drive advanced service ที่เปิดไว้ใน `appsscript.json` ของคุณอยู่แล้ว เพื่อแชร์ไฟล์โดยไม่ส่งอีเมลแจ้งเตือน)
5. เพิ่มอีเมลหัวหน้า/สมาชิกในหน้า **สารบรรณ → หน่วยงาน** (สิทธิ์รับ-ดูหนังสือของแต่ละคนมาจากตรงนี้)

## ใครทำอะไรได้
| บทบาท | ได้อะไร |
|---|---|
| ทุกคนที่เข้าระบบ | **งานของฉัน** (หนังสือที่ส่งถึงหน่วยงาน/ถูกมอบหมาย), ติดตามเฉพาะเรื่องที่เกี่ยวข้อง, รับเรื่อง/ปิดงาน/ส่งคืน |
| หัวหน้าหน่วย / ผู้รักษาราชการแทน | มอบหมายงานให้สมาชิก, เห็นหนังสือลับที่ส่งถึงหน่วย (ผู้รักษาการหมดสิทธิ์เองเมื่อพ้นวันที่กำหนด) |
| เจ้าหน้าที่สารบรรณ | ลงรับ · ส่งออก · จองเลข · ยกเลิกเลข · แก้ไข · ส่งต่อ · ทะเบียน · เลขทะเบียน · ส่งออก CSV |
| ผู้บริหาร | เห็นทุกเรื่อง (รวมลับ) · ภาพรวม · **สั่งการ** |
| ผู้ดูแลระบบ | ทุกอย่าง + หน่วยงาน, ลดชั้นความลับ, ยกเลิกเลขของงานที่ดำเนินการแล้ว |

## สถานการณ์ที่ออกแบบไว้ (และทดสอบอัตโนมัติ)
| สถานการณ์ | วิธีที่ระบบจัดการ |
|---|---|
| ลงรับพร้อมกันหลายเครื่อง/คลิกซ้ำ/เน็ตหลุดแล้วกดใหม่ | ออกเลขใน lock เดียว · ทุกคำขอมี `rid` — กดซ้ำได้ **ไม่ได้เลขที่สอง** |
| สองคนลงรับหนังสือจากคิวฉบับเดียวกัน | คนที่สองได้ข้อความ “ถูกลงรับแล้ว (เลขรับ …)” |
| หนังสือซ้ำ (เลขที่+ผู้ส่ง หรือเรื่อง+ผู้ส่ง) | เตือนก่อนลงรับ — ต้องกดยืนยันจึงลงซ้ำ (แจ้งถึงฉบับที่อยู่ในคิวด้วย) |
| ข้ามปี 31 ธ.ค. → 1 ม.ค. | เลขเริ่ม 1 ใหม่ตามปีปฏิทิน (เวลาไทย) ใช้ปี พ.ศ. ต่อท้าย เช่น `1/2570` |
| ลงรับผิด / ลงซ้ำ | **ห้ามลบเลข** — ยกเลิกพร้อมเหตุผล เลขคงอยู่ในทะเบียนสถานะ “ยกเลิก” ใช้ซ้ำไม่ได้ · งานที่ดำเนินการแล้วต้องเป็นผู้ดูแลระบบ |
| เลขขาดช่วง | หน้า “เลขทะเบียน” แจ้งเลขที่หายจากลำดับ (ทะเบียนที่ถูกต้องห้ามมีช่องว่างที่ไม่มีคำอธิบาย) |
| ทะเบียนกระดาษเดิมเลขไปถึงแล้ว | ระบุ “เลขเริ่มต้นเอง” ได้ (ข้ามเลขได้ แต่ถอยหลัง/ซ้ำไม่ได้) · เลขที่ลงในหน้า Inbox เดิมถูกนับต่อโดยอัตโนมัติ |
| หนังสือลับ/ลับมาก/ลับที่สุด | เฉพาะผู้ได้รับอนุญาตลงรับและเห็นเนื้อหา · เจ้าหน้าที่ทั่วไปเห็นแถวถูกปิดบัง · ค้นหา/ส่งออกไม่เผยเรื่อง · ไม่แชร์ไฟล์ Drive ให้สมาชิกทั่วไป · ไม่นำเข้าคลังข้อมูล |
| ด่วน/ด่วนมาก/ด่วนที่สุด | กำหนดเสร็จอัตโนมัติตามวันทำการและวันหยุด (หรือใช้วันที่ที่ระบุในหนังสือ) · เลยกำหนดขึ้นสีแดง ทั้งในภาพรวม ทะเบียน และงานของฉัน |
| หัวหน้าลา/รักษาราชการแทน | ระบุผู้รักษาการ + วันที่สิ้นสุด — สิทธิ์ย้ายอัตโนมัติและหมดเองเมื่อพ้นวัน |
| ส่งต่อผิดหน่วย | หน่วยกด “ส่งคืน” พร้อมเหตุผล → สถานะ “ส่งคืน รอส่งต่อใหม่” ขึ้นเตือนที่ภาพรวม → ส่งต่อใหม่ |
| ผู้บริหารสั่งการ | บันทึกข้อสั่งการ + มอบหลายหน่วย พร้อมกำหนดเสร็จเฉพาะหน่วย · หนังสือเวียนติดตามการ “ทราบ” รายหน่วย |
| หนังสือส่งซ้ำภายในไม่กี่นาที | ปฏิเสธถ้าเรื่อง+ผู้รับ+ช่องทางเดียวกันภายใน 10 นาที |
| หนังสือเวียน (ว) | นับเลข “ว” แยกจากเลขทะเบียนส่งปกติ · เลขที่หนังสือสร้างจากคำนำหน้าของทะเบียน |
| ร่างหนังสือยังไม่เสร็จแต่ต้องมีเลข | **จองเลข** → ใช้ออกหนังสือภายหลัง · ค้างเกิน 7 วันขึ้นเตือน · ยกเลิกพร้อมเหตุผล |
| ตอบหนังสือรับ | ผูกกับเลขรับ → หนังสือรับถูกบันทึก “ตอบแล้ว …” |
| ไฟล์ปลอม/ใหญ่เกิน | ตรวจไบต์ต้นไฟล์ (PDF/JPG/PNG/WebP/Office) ≤ 10 MB · แนบได้เฉพาะไฟล์ที่อัปโหลดผ่านหน้านี้ |
| ข้อมูลผู้ป่วยในหนังสือ | แจ้งเตือนตามนโยบายแอป · OCR/อ่านฟิลด์ทำ **บนเครื่องผู้ใช้** ไม่ส่งออกอินเทอร์เน็ต · Log เก็บเฉพาะรหัส/เลข ไม่เก็บเรื่อง |
| หลายทะเบียน (กองกลาง/หน่วย) | หน่วยที่ติ๊ก “มีทะเบียนของตนเอง” ได้ตัวนับและคำนำหน้าเลขแยก |

## ความสอดคล้องที่ตรวจพบและแก้
1. **เลขรับสองชุด** — หน้า Inbox เดิมนับเอง ส่วนทะเบียนใหม่นับอีกชุด → รวมเป็นตัวนับเดียว (`sarRegisterFromInbox`) และหนังสือที่รับจาก Inbox ปรากฏในทะเบียนทันที
2. **Code.gs ที่คุณอัปโหลดไม่มีการเชื่อม Inbox** (ใน GitHub มี) และ **Analytics.gs ของคุณใหม่กว่า GitHub** → ไฟล์ `Code.gs` ที่ส่งไปรวมของคุณ + Inbox + Saraban; อย่าเอา Analytics จาก GitHub ทับ
3. `appsscript.json` ใน repo ไม่ตรงของจริง (ขาด Drive/Docs advanced service และ scope) → ใช้ฉบับของคุณ
4. หน้า Inbox แก้ไขหนังสือที่รับแล้วได้ ทำให้ทะเบียนไม่ตรง → ล็อก ให้แก้ที่หน้าสารบรรณ (มีประวัติแก้ไข)
5. ช่องทาง `telegram` ถูกเพิ่มในตัวเลือกช่องทางรับ ให้ข้อมูลจากคิวตรงกับทะเบียน
6. `api.js`: เพิ่มคำสั่งอ่านอย่างเดียวในรายการ retry อัตโนมัติ (คำสั่งเขียน/ออกเลขไม่ retry อัตโนมัติ)
7. ประวัติการใช้งานเพิ่มชื่อเครื่องมือ “สารบรรณ”

## ข้อจำกัดที่ควรรู้
- ไม่มี AI อ่านหนังสือ: ใช้ข้อความใน PDF/OCR + กฎอ่านฟิลด์ แล้วให้เจ้าหน้าที่ตรวจเสมอ (ไฮไลต์ช่องที่อ่านได้) — OCR ต้องมีไฟล์เอนจิน (`npm run ocr:fetch`)
- ตราประทับวางมุมขวาบนหน้า 1 (หน้าที่หมุนไว้อาจตำแหน่งเพี้ยน) · เก็บทั้งไฟล์ต้นฉบับและฉบับประทับตรา
- ลายเซ็นอิเล็กทรอนิกส์/การเสนอเซ็นตามสายงานหลายขั้น และการแจ้งเตือนอีเมล/Telegram ยังไม่รวมในรุ่นนี้
- Google Sheets เหมาะกับหลักพันฉบับต่อปี (อ่านย้อนหลังล่าสุด ~9,000 แถว) — ถ้าปริมาณสูงกว่านี้ควรย้ายฐานข้อมูล
- เลขรับ/ส่งเริ่มใหม่ทุกปีปฏิทินตามระบบเดิมของคุณ — ตรวจสอบกับระเบียบงานสารบรรณของหน่วยงานก่อนใช้จริง
